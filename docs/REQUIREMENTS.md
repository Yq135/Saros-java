## 1. 项目背景与定位

Saros 是一个「联网搜索 + 检索增强生成（RAG）」的个性化智能知识库系统。核心理念：**沉淀即永恒** —— 不仅帮用户获取外部信息，更把外部知识转化为私有资产，让「获取的新知识」与「过去的旧总结」碰撞、复用。

产品形态：**本地 Web 应用**（浏览器访问 localhost，无登录、单用户、中文界面）。

## 2. 目标与范围

**本期目标**：完成四大模块的可用闭环 —— 外部知识获取（搜索 / 网页 / 视频）→ 内化沉淀 → 复用关联。

**非目标（明确不做）**：多用户与账号体系、移动端 App、云端部署、付费搜索/转录 API、除 B 站外的视频平台。

## 3. 用户与使用场景

- 用户：开发者本人，单机 macOS（Apple Silicon）使用
- 场景 A：遇到问题 → 联网问答（可同一会话多轮追问）→ 回答附引用与标签 → 相关历史可查
- 场景 B：读到好文章 → 传链接 → 生成「读后掌握」问题 → 验证理解
- 场景 C：看 B 站视频学习 → 传链接 → 自动归档视频/字幕 → 带时间点大纲 + 出题 → 点击时间点跳转播放
- 场景 D：学到的知识 → 手打录入（禁止粘贴）→ 打标签沉淀 → 日后提问自动关联引用

## 4. 功能需求

### 模块一：联网问答

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1.1 | 联网搜索 | 用户提问后使用**免费搜索源**（DuckDuckGo 主力，Bing/百度抓取兜底）检索，合并去重取 top 8-10 条 |
| FR-1.2 | 混合检索沉淀知识 | 检索已沉淀知识点（**仅手打笔记**）：语义相似度（pgvector KNN）+ 标签命中 + 关键词重叠，加权打分取 top 5 |
| FR-1.3 | 生成回答 | LLM 合成中文 Markdown 回答，引用搜索来源 `[n]` 标注；**沉淀知识与搜索结果冲突时以沉淀为准并说明**；资料不足须明说，不得编造 |
| FR-1.4 | 流式输出 | 前端先收到来源与引用的沉淀列表，随后答案流式渲染 |
| FR-1.5 | 自动标签 | 回答完成后自动生成 3-5 个中文推荐标签（文本），仅作转手打笔记时的候选建议；**仅会话首轮生成**，追问轮不生成 |
| FR-1.6 | 问答历史 | 会话列表（**关键词筛选**，匹配标题/问题/答案）、会话详情（按时间顺序展示多轮问答，每轮含来源、引用的沉淀知识、推荐标签）、删除会话（级联删除轮次） |
| FR-1.7 | 降级策略 | 搜索全挂但有沉淀命中 → 仅基于沉淀回答并注明；两者均不可用 → 明确报错 |
| FR-1.8 | 多轮对话 | 同一会话内可连续追问，LLM 携带该会话最近若干轮（问题全文 + 回答截断，轮数可调）作为上下文；**每轮独立执行联网搜索 + 沉淀检索**（追问可能引入新话题）；每轮回答内 `[n]` 对应该轮搜索来源，历史轮次仅作上下文、不带编号；**对话内容只存历史，绝不写入沉淀**（沉淀入口仅模块四） |

### 模块二：网页出题

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-2.1 | 正文抽取 | 传入 URL，trafilatura 抽取正文；失败兜底 Jina Reader（`r.jina.ai/{url}`） |
| FR-2.2 | 生成问题 | 基于正文生成 3-5 个「读完后能掌握内容」的问题，每题附参考答案 |
| FR-2.3 | 入库 | 正文、问题、标签入库；列表/详情（正文折叠预览、参考答案点击展开）/删除 |
| FR-2.4 | 加载反馈 | 同步任务约 20-40s，前端分段展示「正在提取正文… / 正在生成题目…」 |

### 模块三：B站视频知识提取（⚠️ 实施细节待讨论，见 §9）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-3.1 | 链接校验 | 仅支持 Bilibili 视频链接（BV 号正则 + b23.tv 短链解析），非 B 站立即报错 |
| FR-3.2 | 下载策略 | yt-dlp 下载字幕到本地 `data/media/{bvid}/`（官方 CC 优先，AI 字幕 ai-zh 兜底）；**下载不到字幕才下载音频**（audio-only 流，供音频模式使用）；**不下载视频**（详情页用 B 站官方在线播放器）；**使用用户提供的 cookie**（见 FR-3.8）。**「跳过字幕下载」开关**（设置页，默认关）：开启后跳过 CC/AI 字幕直接走音频模式——ASR 转写带断句标点，大纲/出题质量更高，更耗时 |
| FR-3.3 | 无字幕兜底（音频模式） | 官方 CC 与 B 站 AI 字幕均不可得 → 直接下载 audio-only 流（B 站 DASH 音视频分离）→ ffmpeg 约 5 分钟切片 → **自建 ASR**（mlx-qwen3-asr，OpenAI 兼容接口）转写带精确时间戳文本 → 与字幕模式共用大纲/出题流程 |
| FR-3.4 | 大纲提炼 | 定位：**大致框架**，让人知道哪个时间点讲什么内容（非逐句笔记）。**字幕全文（或音频模式的 ASR 转写全文）一次喂给 LLM**（超长截断保护）→ 生成带 `[MM:SS]` 锚点的大纲（时间戳只允许使用文本中真实存在的时间点，字幕/转写均有精确时间戳） |
| FR-3.5 | 生成问题 | 基于大纲生成 5-8 个掌握类问题，每题关联时间点 |
| FR-3.6 | 任务管理 | 后台异步执行：状态机 + 进度百分比 + 步骤中文描述；前端轮询展示；**同时只跑一个视频任务**，其余排队；失败可重试（已下载文件跳过，断点续跑）；删除任务同时清理媒体文件，并**级联删除视频知识**（大纲/题目/字幕段）；服务重启后中间态任务标记失败、可重试。注：**「沉淀即永恒」仅针对手打笔记**，视频知识随任务删除不保留 |
| FR-3.7 | 详情页 | 内嵌 **B 站官方在线播放器**（iframe，支持拖动/全屏）；大纲时间戳可点击跳转对应位置（iframe 带 `?t=` 参数重载）；字幕段列表可点击跳转（音频模式无字幕段）；题目参考答案折叠 |
| FR-3.8 | cookie 管理 | 用户提供 B 站 cookie（配置项）；下载 403 或 cookie 失效时明确提示用户更新 |

### 模块四：知识沉淀

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-4.1 | 手打录入 | 知识点输入框**禁止复制粘贴**（粘贴事件、快捷键、拖拽三层拦截），目的是强制逐字输入以加深记忆；拦截时提示「为加深记忆，请手动输入」 |
| FR-4.2 | 打标签 | 录入时选择/创建标签，标签自动补全 |
| FR-4.3 | 知识查询页（独立导航） | 分页列表（标签精确 + 关键词 ILIKE + **掌握度等值筛选**），编辑（同样禁粘贴）/删除入口在此页；筛选变化重置回第 1 页；删光末页自动回退一页 |
| FR-4.4 | 嵌入入库 | 知识点写入 pgvector 向量库，供模块一混合检索与语义查询引用 |
| FR-4.5 | 语义查询（小RAG） | 自然语言输入 → BGE 编码 → pgvector KNN 返回 top-K 条笔记原文 + 相似度分数；**纯检索不生成、不调用 LLM**；top_k 1-50（默认 10） |
| FR-4.6 | 页面拆分 | 知识沉淀页只保留录入提交 + 勉励话占位（文案待定）+ 查询页入口；列表/编辑/删除全部移入知识查询页 |

## 5. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 本地部署：前后端进程运行在本机，数据不出本机 |
| NFR-2 | 成本控制：搜索用免费源、嵌入用本地模型，费用仅 LLM 调用（国产模型）及音频模式的多模态调用 |

| NFR-4 | 可用性：任务失败原因明确、可恢复；长任务有进度反馈 |

## 6. 技术架构约定

| 用途 | 选择 |
|---|---|
| 后端 | Python 3.10 + FastAPI + uvicorn + pydantic-settings |
| 数据库 | **PostgreSQL + pgvector**（元数据 + 向量同库；需要本机 PG 服务，连接配置走 .env） |
| LLM | openai SDK 指向 DeepSeek 等国产模型（`LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 可配） |
| 嵌入 | sentence-transformers + BAAI/bge-small-zh-v1.5（512 维，本地 CPU） |
| 搜索 | ddgs（DuckDuckGo）+ Bing/百度抓取兜底，接口化可插拔 |
| 网页抽取 | trafilatura + Jina Reader 兜底 |
| 视频 | yt-dlp + ffmpeg | 下载/归档；无字幕时 ffmpeg 提取音频 |
| 音频理解 | **自建 ASR：mlx-qwen3-asr**（另一台机器部署，OpenAI 兼容接口，Qwen3-ASR-1.7B MLX） | 仅无 CC/AI 字幕时启用：音频切片 → ASR 转写带时间戳文本 → 复用字幕模式流程 |
| 前端 | Vue 3 + Vite + Element Plus + vue-router（marked + DOMPurify 渲染） |

> 变更记录：原方案 SQLite + sqlite-vec 已改为 **PostgreSQL + pgvector**（2026-08-14 用户确认）。

## 7. 数据模型概要

> 完整字段以 `db_init.sql` 为准。

- `users`：用户（单用户，user_id 应用层约定默认 1）
- `manual_knowledge`：手打笔记（沉淀知识）
- `tags`：正式标签（仅绑定手打笔记，随笔记级联删除）
- `qa_conversations`（会话：标题取首问截断，删除级联删轮次）+ `qa_messages`（会话内轮次：问题、答案、来源 JSON、引用的沉淀 id、推荐标签文本，标签仅首轮生成）
- `web_articles` + `webpage_questions`（题干 + 参考答案）
- `bilibili_tasks`（bvid、url（含 p 参数）、状态 PENDING/PROCESSING/SUCCESS/FAILED、进度、步骤、错误）+ `bilibili_videos`（标题、mode（CC/AI/AUDIO）、字幕/音频路径（不存视频）、大纲）+ `video_segments`（带起止时间戳的文本段：字幕模式为字幕段，音频模式为 ASR 转写段）+ `video_questions`（带时间点 + 参考答案）
- `embeddings`（512 维向量，当前仅嵌入手打笔记，含 user_id）
