# Saros DB 数据库设计文档

> 版本：v0.6（2026-08-30）。**字段定义以仓库根目录 `db_init.sql` 为准**，本文档为解读与业务逻辑说明。

## 1. 设计概述

| 项目 | 说明 |
|:---|:---|
| 数据库名称 | `saros_db` |
| 数据库类型 | PostgreSQL（推荐版本 14+） |
| 核心依赖 | `pgvector` 扩展（用于向量相似度搜索） |
| 主键策略 | 统一使用 `BIGSERIAL`（对应 `BIGINT`），防止未来数据量溢出 |
| 标签策略（方案B） | 正式标签仅属于手打笔记；问答/网页/视频的 AI 标签为 `suggested_tags` 推荐文本，仅作「转笔记时的候选建议」；其他模块历史筛选以关键词为主 |
| 检索范围 | embeddings 当前**仅嵌入手打笔记**（source_type='MANUAL'），问答只检索沉淀知识 |
| 审计追踪 | 核心表均包含 `user_id`、`created_at`、`updated_at` 字段；`updated_at` 由触发器自动更新 |
| 删除语义 | 删除视频任务级联删除视频知识（大纲/题目/字幕段）并清理媒体文件；「沉淀即永恒」仅针对手打笔记 |

## 2. 表结构定义

### 2.1 用户表（users）

当前单用户、无登录，`user_id` 由应用层约定（默认 1）。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 用户ID |
| username | VARCHAR(50) | NOT NULL, UNIQUE | — | 用户名 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |

### 2.2 手打知识表（manual_knowledge）

模块四核心表，正式标签的唯一宿主；向量存 `embeddings` 表。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 创建人ID |
| content | TEXT | NOT NULL | — | 知识点内容（纯文本/Markdown） |
| mastery_level | INT | CHECK (0-5) | 0 | 掌握程度 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMPTZ | 触发器自动更新 | CURRENT_TIMESTAMP | 更新时间 |

### 2.3 正式标签表（tags）

仅关联手打笔记。同一笔记下标签名不重复（`UNIQUE(manual_knowledge_id, name)`，该约束索引同时覆盖按笔记查标签的查询）。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 标签ID |
| manual_knowledge_id | BIGINT | NOT NULL, REFERENCES manual_knowledge(id) ON DELETE CASCADE | — | 所属笔记ID（级联删除） |
| name | VARCHAR(100) | NOT NULL | — | 标签名称 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |

索引：`idx_tags_name`（name），用于标签自动补全。

### 2.4 联网问答表（qa_conversations + qa_messages）

> v0.6 决议：原 `qa_sessions` 单表拆为会话表 + 轮次表（支持同一会话多轮追问）。旧表无数据，直接删除即可（`DROP TABLE IF EXISTS qa_sessions CASCADE;`）。

**qa_conversations（会话表）**：一次围绕主题的多轮探讨。标题取首问截断（非 LLM 生成）；删除会话级联删除全部轮次。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 会话ID |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 所属用户ID |
| title | VARCHAR(255) | NOT NULL | '' | 会话标题（首问前 30 字截断） |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMPTZ | 触发器自动更新 | CURRENT_TIMESTAMP | 更新时间 |

**qa_messages（轮次表）**：一问一答一条记录。对话内容只存历史，绝不写入沉淀（沉淀入口仅模块四）。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 轮次ID |
| conversation_id | BIGINT | NOT NULL, REFERENCES qa_conversations(id) ON DELETE CASCADE | — | 所属会话ID（级联删除） |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 提问人ID |
| question | TEXT | NOT NULL | — | 用户提问 |
| answer | TEXT | — | — | LLM 生成的最终回答 |
| search_sources | JSONB | — | — | 本轮联网搜索来源列表 |
| referenced_knowledge_ids | BIGINT[] | — | — | 引用的沉淀知识 ID 列表（manual_knowledge.id） |
| suggested_tags | TEXT[] | — | — | AI 推荐的标签（非正式，仅会话首轮生成） |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |

索引：`idx_qa_messages_conversation`（conversation_id, created_at），按会话取轮次（时间升序展示）。

### 2.5 网页文章表（web_articles）

模块二：正文与文章元信息，题目存 `webpage_questions` 子表。题目生成失败不影响正文入库。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 创建人ID |
| url | VARCHAR(1024) | NOT NULL, UNIQUE | — | 原始 URL |
| title | VARCHAR(255) | — | — | 网页标题 |
| content | TEXT | NOT NULL | — | 抽取的正文 |
| suggested_tags | TEXT[] | — | — | AI 生成的推荐标签（非正式） |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMPTZ | 触发器自动更新 | CURRENT_TIMESTAMP | 更新时间 |

### 2.6 网页题目表（webpage_questions）

3-5 道「读后掌握」问题，每题附参考答案（前端折叠展示）。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| article_id | BIGINT | NOT NULL, REFERENCES web_articles(id) ON DELETE CASCADE | — | 所属文章ID（级联删除） |
| question | TEXT | NOT NULL | — | 题干 |
| reference_answer | TEXT | — | — | 参考答案 |
| sort_order | INT | — | 0 | 题目顺序 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |

索引：`idx_webpage_questions_article`（article_id）。

### 2.7 B站视频任务表（bilibili_tasks）

模块三状态机表，用于追踪进度与断点续传。同一视频不可重复提交（`UNIQUE(user_id, bvid)`）。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 创建人ID |
| bvid | VARCHAR(20) | NOT NULL | — | 视频 BV 号（与 user_id 联合唯一） |
| status | VARCHAR(20) | NOT NULL, CHECK (PENDING/PROCESSING/SUCCESS/FAILED) | 'PENDING' | 任务状态 |
| progress | INT | — | 0 | 进度百分比（0-100） |
| step_desc | VARCHAR(255) | — | — | 当前步骤中文描述 |
| error_msg | TEXT | — | — | 失败原因 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMPTZ | 触发器自动更新 | CURRENT_TIMESTAMP | 更新时间 |

### 2.8 B站视频知识表（bilibili_videos）

任务创建时即初始化本表记录，一任务一视频（`task_id UNIQUE NOT NULL`）；任务删除时级联删除本行及全部子表数据，应用层同时清理媒体文件。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| task_id | BIGINT | NOT NULL, UNIQUE, REFERENCES bilibili_tasks(id) ON DELETE CASCADE | — | 关联任务ID（唯一） |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 创建人ID |
| bvid | VARCHAR(20) | NOT NULL, UNIQUE | — | 视频 BV 号 |
| title | VARCHAR(255) | — | — | 视频标题 |
| mode | VARCHAR(10) | CHECK (CC/AI/AUDIO) | — | 处理模式：CC=官方CC字幕 / AI=B站AI字幕 / AUDIO=音频模式（无字幕）；任务完成后填充 |
| outline | TEXT | — | — | 带时间戳的大纲（CC/AI 为精确锚点；AUDIO 为切片起点粗粒度锚点） |
| local_video_path | VARCHAR(1024) | — | — | 本地视频路径 |
| local_audio_path | VARCHAR(1024) | — | — | 本地音频路径 |
| local_subtitle_path | VARCHAR(1024) | — | — | 本地字幕文件路径（AUDIO 模式为空） |
| suggested_tags | TEXT[] | — | — | AI 生成的推荐标签（非正式） |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMPTZ | 触发器自动更新 | CURRENT_TIMESTAMP | 更新时间 |

### 2.9 字幕段表（video_segments）

详情页字幕段列表可点击跳转。CC/AI 模式有数据；AUDIO 模式无数据。

### 2.10 视频题目表（video_questions）

5-8 道「看后掌握」问题，每题关联时间点（可跳转）与参考答案。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |

### 2.11 向量嵌入表（embeddings）

统一向量检索入口。**当前仅嵌入手打笔记**（source_type='MANUAL'，source_id=manual_knowledge.id），维度 512 与 `bge-small-zh-v1.5` 一致。

| 字段名 | 类型 | 约束 | 默认值 | 说明 |
|:---|:---|:---|:---|:---|
| id | BIGSERIAL | PRIMARY KEY | — | 主键ID |
| user_id | BIGINT | NOT NULL, REFERENCES users(id) | — | 所属用户ID |
| source_type | VARCHAR(20) | NOT NULL | 'MANUAL' | 来源类型标识（当前仅 MANUAL，预留扩展） |
| source_id | BIGINT | NOT NULL | — | 来源表的主键ID（当前为 manual_knowledge.id） |
| chunk_content | TEXT | NOT NULL | — | 分块后的文本内容 |
| embedding | VECTOR(512) | — | — | 向量数据 |
| created_at | TIMESTAMPTZ | — | CURRENT_TIMESTAMP | 创建时间 |

索引：HNSW（embedding, vector_cosine_ops）、`idx_embeddings_source`（source_type, source_id）、`idx_embeddings_user`（user_id）。

## 3. 索引汇总

| 索引名 | 表 | 列 | 类型 | 用途 |
|:---|:---|:---|:---|:---|
| tags_manual_knowledge_id_name_key | tags | (manual_knowledge_id, name) | UNIQUE B-tree | 同笔记标签去重 + 按笔记查标签 |
| idx_tags_name | tags | name | B-tree | 标签自动补全搜索 |
| bilibili_tasks_user_id_bvid_key | bilibili_tasks | (user_id, bvid) | UNIQUE B-tree | 同一视频不可重复提交 |
| bilibili_videos_task_id_key | bilibili_videos | task_id | UNIQUE B-tree | 一任务一视频 |
| idx_webpage_questions_article | webpage_questions | article_id | B-tree | 按文章查题目 |
| idx_video_segments_video | video_segments | (video_id, start_ts) | B-tree | 按视频+时间顺序查字幕段 |
| idx_video_questions_video | video_questions | video_id | B-tree | 按视频查题目 |
| (unnamed) | embeddings | embedding | HNSW | 向量余弦相似度检索 |
| idx_embeddings_source | embeddings | (source_type, source_id) | B-tree | 按来源类型和ID查询/删除 |
| idx_embeddings_user | embeddings | user_id | B-tree | 按用户查询/清理向量 |

## 4. 业务逻辑闭环说明

### 4.1 标签流转逻辑（方案B）

| 阶段 | 说明 |
|:---|:---|
| 生成阶段（推荐态） | 用户处理网页、视频或问答时，LLM 生成一组标签字符串，存入各自表的 `suggested_tags`（TEXT[]）。仅为文本，与 `tags` 表无关联 |
| 沉淀阶段（正式态） | 用户将内容转化为手打笔记时，前端展示 `suggested_tags` 供用户选择，用户可勾选建议标签或手动新建标签 |
| 落地 | 系统插入 `manual_knowledge` 记录后，将用户确认的标签插入 `tags` 表并绑定 `manual_knowledge_id` |
| 筛选 | 标签筛选仅对**手打笔记**有效（查 `tags` 表）；问答/网页/视频历史筛选以**关键词**为主 |

### 4.2 向量检索逻辑

1. `embeddings` 表作为统一检索入口，**当前仅嵌入手打笔记**（source_type='MANUAL'）
2. 检索流程：先通过向量相似度（HNSW 索引）在 `embeddings` 表中找到 Top-K 候选，结合 `tags` 标签命中与关键词重叠加权打分，取 top 5；再按 `source_id` 回查 `manual_knowledge` 获取完整内容
3. `source_type`/`source_id` 的多态结构为未来扩展（网页/视频入检索）预留

### 4.3 数据维护规则

| 操作 | 行为 |
|:---|:---|
| 删除手打笔记 | 数据库级联删除 `tags`；应用层同步删除 `embeddings` 中对应向量（source_type='MANUAL' AND source_id=笔记id） |
| 编辑手打笔记 | 应用层同步更新 `embeddings` 中对应向量 |
| 删除视频任务 | 数据库级联删除 `bilibili_videos` 及其子表（segments/questions）；应用层同时清理 `data/media/{bvid}/` 媒体文件。「沉淀即永恒」仅针对手打笔记，视频知识不保留 |
| 删除网页文章 | 级联删除 `webpage_questions` |
| 删除用户 | 应用层级联删除该用户所有业务记录及向量（`users` 表未设级联） |

### 4.4 表关系总览

```
users (1) ───── (N) manual_knowledge ───── (N) tags            ← 正式标签仅属于手打笔记
                └────── (N) embeddings (source_type='MANUAL')  ← 当前唯一嵌入来源

users (1) ───── (N) qa_conversations ───── (N) qa_messages  ← 删除会话级联删除轮次

users (1) ───── (N) web_articles ───── (N) webpage_questions

users (1) ───── (N) bilibili_tasks ───── (1) bilibili_videos
                                          ├────── (N) video_segments    （CC/AI 模式有数据）
                                          └────── (N) video_questions
```

## 5. 初始化与变更

- 完整建表脚本见仓库根目录 **`db_init.sql`**（唯一权威来源）
- 通用触发器 `update_updated_at_column()`：所有含 `updated_at` 的表在 UPDATE 时自动刷新该字段
- 变更记录：
  - v0.6（2026-08-18）：`qa_sessions` 拆为 `qa_conversations`（会话）+ `qa_messages`（轮次，级联删除），支持多轮追问；推荐标签仅会话首轮生成（本文档 v0.6 同步该决议）
  - v0.5（2026-08-17）：嵌入维度 1024→512；出题拆分子表（webpage_questions / video_questions）；新增 video_segments；去掉 has_subtitle，改用 mode（CC/AI/AUDIO）；task_id NOT NULL UNIQUE；任务表 UNIQUE(user_id, bvid)；embeddings 增加 user_id；状态值统一 PENDING/PROCESSING/SUCCESS/FAILED；补充 CHECK 约束与 updated_at 触发器
